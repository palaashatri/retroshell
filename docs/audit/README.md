# Audit evidence policy

Files in this directory are historical engineering notes and generated audit
artifacts. They are **not** automatically authoritative merely because their
filename contains `VERIFIED`, `EVIDENCE`, or `AUDIT`.

Current rules:

1. Source presence is not runtime proof.
2. Unit tests prove only the unit under test.
3. A screenshot proves only what is visible in that frame.
4. Process launch does not prove window mapping or interaction.
5. Interactive features require recorded input events plus observed compositor
   state/pixels before and after the action.
6. Hardware claims (DRM/KMS, cursor planes, HDR, VRR, GPU acceleration) require
   execution on compatible hardware.
7. Any report generated by `scripts/de_readiness_harness.py` leaves interaction
   fields `UNTESTED` unless an external interaction driver supplies evidence.

The source tree and current runtime behavior take precedence over older prose.
When QA is performed, preserve exact commands, commit hash, environment,
process/socket topology, logs, and artifacts.
